# LangChain / LangGraph 消息协议

> 面向：想搞懂「对话在框架里怎么表示、怎么记住」的读者。本文自包含，不依赖某个项目目录。  
> 概念与字段对齐 **langchain-core 1.x**（核对过 1.8.1 的消息类字段）；API 随小版本可能微调，以你安装的包为准。

## 1. 先跑一个完整 Demo（建立直觉）

下面是一份**可整文件保存、直接运行**的脚本（建议存成 `messages_protocol_demo.py`）。

- **不需要** Ollama / API Key：用脚本内的假模型 `DemoLLM` 演协议。  
- **需要** 已安装：`langchain`、`langchain-core`、`langgraph`（版本接近 1.x 即可）。  
- 它会跑通两件事：① 一轮「用户 → 调工具 → 工具结果 → 最终回答」；② 同一 `thread_id` 下第二轮只交新句，历史由 `MemorySaver` 拼回。

```python
"""messages_protocol_demo.py — 消息协议完整可运行 Demo（无需真模型）"""

from __future__ import annotations

from typing import Any

from langchain.agents import create_agent
from langchain_core.language_models.chat_models import BaseChatModel
from langchain_core.messages import AIMessage, BaseMessage, HumanMessage, ToolMessage
from langchain_core.outputs import ChatGeneration, ChatResult
from langchain_core.tools import tool
from langgraph.checkpoint.memory import MemorySaver


@tool
def calculator(expression: str) -> str:
    """计算简单加法。本 demo 为演示协议，仅识别 1+1。"""
    if expression.replace(" ", "") == "1+1":
        return "2"
    return f"unsupported: {expression}"


class DemoLLM(BaseChatModel):
    """假模型：按消息列表决定「调工具 / 最终答 / 回忆上一轮结果」。"""

    @property
    def _llm_type(self) -> str:
        return "demo-scripted"

    def bind_tools(self, tools: Any, **kwargs: Any):
        # create_agent 会调用；假模型不需要真绑定
        return self

    def _generate(
        self,
        messages: list[BaseMessage],
        stop: list[str] | None = None,
        run_manager: Any = None,
        **kwargs: Any,
    ) -> ChatResult:
        last_human = next(
            (m for m in reversed(messages) if isinstance(m, HumanMessage)),
            None,
        )
        text = str(last_human.content) if last_human else ""

        # 本轮用户之后已有 ToolMessage → 根据工具结果给最终句
        if last_human is not None:
            after = messages[messages.index(last_human) + 1 :]
            for m in after:
                if isinstance(m, ToolMessage):
                    msg = AIMessage(content=f"计算结果是 {m.content}。")
                    return ChatResult(generations=[ChatGeneration(message=msg)])

        # 追问「刚才结果」→ 从历史里找 ToolMessage（体现跨轮记忆）
        if any(k in text for k in ("结果", "多少", "刚才")):
            for m in reversed(messages):
                if isinstance(m, ToolMessage):
                    msg = AIMessage(content=f"刚才算出来是 {m.content}。")
                    return ChatResult(generations=[ChatGeneration(message=msg)])

        # 话里像计算 → 发出 tool_calls（Action）
        if any(ch in text for ch in "+-*/"):
            msg = AIMessage(
                content="",
                tool_calls=[
                    {
                        "name": "calculator",
                        "args": {"expression": "1+1"},
                        "id": "call_1",
                        "type": "tool_call",
                    }
                ],
            )
            return ChatResult(generations=[ChatGeneration(message=msg)])

        msg = AIMessage(content=f"收到：{text}")
        return ChatResult(generations=[ChatGeneration(message=msg)])


def dump_messages(messages: list[BaseMessage]) -> None:
    for i, m in enumerate(messages, 1):
        extra = ""
        if getattr(m, "tool_calls", None):
            extra = f" tool_calls={m.tool_calls}"
        elif getattr(m, "tool_call_id", None):
            extra = f" tool_call_id={m.tool_call_id}"
        print(f"  {i}. [{m.type}] {str(m.content)[:60]!r}{extra}")


def main() -> None:
    agent = create_agent(
        model=DemoLLM(),
        tools=[calculator],
        system_prompt="你是助手；需要计算时调用 calculator。",
        checkpointer=MemorySaver(),  # 存档/读档
    )
    # thread_id = 聊天本名字；同一 id 才能跨轮拼历史
    cfg = {
        "configurable": {"thread_id": "demo-thread"},
        "recursion_limit": 10,
    }

    print("=== 第 1 轮：Human → AI(tool_calls) → Tool → AI ===")
    r1 = agent.invoke({"messages": [HumanMessage("帮我算 1+1")]}, cfg)
    dump_messages(r1["messages"])

    print("\n=== 第 2 轮：只交新句；同一 thread_id，历史由 checkpointer 拼回 ===")
    r2 = agent.invoke(
        {"messages": [HumanMessage("我刚才算的结果是多少？")]},
        cfg,
    )
    dump_messages(r2["messages"])
    print("\n最后一条 AI:", r2["messages"][-1].content)


if __name__ == "__main__":
    main()
```

运行：

```bash
python messages_protocol_demo.py
```

预期输出（节选）：

```text
=== 第 1 轮：Human → AI(tool_calls) → Tool → AI ===
  1. [human] '帮我算 1+1'
  2. [ai] '' tool_calls=[{'name': 'calculator', ... 'id': 'call_1', ...}]
  3. [tool] '2' tool_call_id=call_1
  4. [ai] '计算结果是 2。'

=== 第 2 轮：只交新句；同一 thread_id，历史由 checkpointer 拼回 ===
  1. [human] '帮我算 1+1'
  ...
  5. [human] '我刚才算的结果是多少？'
  6. [ai] '刚才算出来是 2。'
```

**先从 Demo 里记住四件事：**

1. 对话是带 `type` 的消息对象列表，不是一大段纯字符串。  
2. 调工具：`AIMessage.tool_calls[].id` 必须等于 `ToolMessage.tool_call_id`。  
3. 每轮调用通常只交**本轮** `HumanMessage`；旧记录靠 **checkpointer** 存取。  
4. **`thread_id`** 决定打开哪一本聊天本；换 id = 新开对话。

下面各节是对上述现象的展开解释。

---


## 2. 白话：框架在管什么？

### 2.1 为什么不是一个大字符串？

微信不是把整段聊天揉成一个 `str`，而是一条一条，每条有「我 / 对方」。  
LangChain 同理：用不同**类**表示角色，公共基类是 `BaseMessage`。

| 白话角色 | 类型 | `type` |
|---|---|---|
| 用户 | `HumanMessage` | `human` |
| 模型（可含「请调某某工具」） | `AIMessage` | `ai` |
| 工具跑完的结果 | `ToolMessage` | `tool` |
| 系统规矩 / 人设 | `SystemMessage` | `system` |

因此用户输入要包成 `HumanMessage(...)`：不是业务上「多包一层」，而是协议要求标明角色。

### 2.2 什么是 `messages` 状态？

Agent / 图运行时有一份状态（小本子），核心一栏叫 **`messages`**：就是当前这份聊天记录列表。

调用时常写成：

```python
agent.invoke(
    {"messages": [HumanMessage(content="你好")]},
    config,   # 见下一节
)
```

含义：**这一次请求里，你至少交上「用户刚说的这句话」**。  
框架会把它合并进小本子的 `messages` 栏（合并策略叫 `add_messages`：默认是追加，不是用你传来的几条把整本历史盖掉）。

### 2.3 什么是 checkpointer？为什么还要 `thread_id`？

§1 的完整 Demo 已经跑过两轮；这里只补定义：

- **Checkpointer**：「存档 / 读档」组件。把状态存成快照（**checkpoint**），下次再取出来。Demo 里是 `MemorySaver()`（进程内存；退出即丢）。生产可换数据库实现。  
- **`thread_id`**：聊天本名字。同一 id → 接着聊；换 id → 新开一本。写在 `config["configurable"]["thread_id"]`。

| 情况 | 效果 |
|---|---|
| 没有 checkpointer | 每轮失忆，只看得见你刚传的那几条 |
| 有 checkpointer，但每次换新 `thread_id` | 每次新开聊天本，也「记不住」 |
| 同一 `thread_id` | 跨轮连续对话（见 §1 第 2 轮） |

术语对照：

```text
state["messages"]   → 小本子上的聊天记录
AnyMessage          → 多种消息类型的统称（联合类型）
add_messages        → 新消息追加进列表的合并规则
checkpointer        → 存档/读档器
thread_id           → 选哪一本聊天本
```

[src: `AgentState.messages` 形如 `Annotated[list[AnyMessage], add_messages]` · langchain.agents]

## 3. 类型树与公共字段

```text
BaseMessage
├── HumanMessage      type="human"
├── AIMessage         type="ai"      (+ tool_calls 等)
├── SystemMessage     type="system"
├── ToolMessage       type="tool"    (+ tool_call_id)
├── FunctionMessage   type="function"   # 旧协议，少用
└── ChatMessage       type="chat"       # 自定义 role，少用
```

流式输出还有 `AIMessageChunk` 等 `*Chunk`，同属「消息家族」。

**`BaseMessage` 常见字段：**

| 字段 | 含义 |
|---|---|
| `content` | 正文（`str`，或多模态 block 列表） |
| `type` | 角色：`human` / `ai` / `system` / `tool` … |
| `name` | 可选名字（如工具名） |
| `id` | 消息 id（删除、去重时有用） |
| `additional_kwargs` | 厂商扩展兜底 |
| `response_metadata` | 响应元数据（如 finish_reason、token） |

日常文本对话：`HumanMessage(content="...")` 或 `HumanMessage("...")` 即可。

## 4. 各类型：先用法 Demo，再解释

### 4.1 `HumanMessage`

```python
from langchain_core.messages import HumanMessage

# 两种等价写法
m1 = HumanMessage(content="北京天气怎么样？")
m2 = HumanMessage("北京天气怎么样？")
assert m1.type == "human"
```

**解释：** 表示用户侧输入。交给 Agent / ChatModel 时，应作为 `messages` 列表里的元素，而不是裸字符串。

### 4.2 `SystemMessage`

```python
from langchain_core.messages import SystemMessage

sys = SystemMessage(content="回答尽量短，不要编造数字。")
assert sys.type == "system"
```

**解释：** 系统约束 / 人设。用 `create_agent(system_prompt="...")` 时也可以传字符串，工厂内部会当作系统侧提示；也可以直接传 `SystemMessage`。  
做上下文压缩时，通常应优先保留 system，避免「规矩丢了」。

### 4.3 `AIMessage` 与 `tool_calls`

```python
from langchain_core.messages import AIMessage

# 纯文本回答
plain = AIMessage(content="你好！")

# 请求调用工具（Action）
with_tools = AIMessage(
    content="",  # 可以空，重点在 tool_calls
    tool_calls=[{
        "name": "get_weather",
        "args": {"city": "北京"},
        "id": "call_weather_1",
        "type": "tool_call",
    }],
)
print(with_tools.tool_calls[0]["name"], with_tools.tool_calls[0]["id"])
```

**`ToolCall` 字典字段：**

| 键 | 含义 |
|---|---|
| `name` | 要调用的工具名 |
| `args` | 参数字典 |
| `id` | 本次调用编号，后面 `ToolMessage` 必须对上 |
| `type` | 可选，常为 `"tool_call"` |

**解释：** `AIMessage` 是模型输出。可以只含自然语言，也可以带 `tool_calls` 表示「请执行这些工具」。还有 `invalid_tool_calls`、`usage_metadata` 等字段，调试时有用。

### 4.4 `ToolMessage`

```python
from langchain_core.messages import ToolMessage

obs = ToolMessage(
    content="北京：晴，22°C",
    tool_call_id="call_weather_1",  # 必须等于上面 AIMessage 里的 id
    name="get_weather",
    status="success",  # 或 "error"
)
assert obs.type == "tool"
```

**解释：** 工具执行结果（Observation）。**`tool_call_id` 必填**；对不上，模型就无法把结果接回那次工具请求。

### 4.5 少用类型

- **`FunctionMessage`**：旧 Function Calling 时代；新代码优先 `ToolMessage` + `tool_calls`。  
- **`ChatMessage`**：自定义 `role`；一般场景用标准四类即可。  
- **`RemoveMessage`**：配合 `add_messages`，按消息 `id` 从历史里删掉某条（摘要替换、编辑线程时）。日常对话不一定用到。

## 5. 一整轮「用户 → 工具 → 最终回答」怎么串

把第 1 节的列表画成流程：

```text
HumanMessage("帮我算 1+1")
        ↓
AIMessage(tool_calls=[{name: calculator, id: call_1, ...}])   # Action
        ↓  运行时执行工具
ToolMessage(content="2", tool_call_id="call_1")               # Observation
        ↓
AIMessage(content="结果是 2。")                                 # 最终回复
```

可读说法：**Thought（多在模型内部）→ Action（`tool_calls`）→ Observation（`ToolMessage`）→ 最终自然语言**。

带 checkpointer 时，多轮只是在同一 `thread_id` 下不断往 `messages` **追加**新的 Human / AI / Tool 消息。

可选：调用时在 config 里设 `recursion_limit`，限制「模型↔工具」来回次数，防止死循环（与消息协议正交，但是常见配套）。

```python
cfg = {
    "configurable": {"thread_id": "demo"},
    "recursion_limit": 15,
}
```

## 6. 序列化长什么样（日志 / 落盘）

消息可 `model_dump()` 成字典，核心形状如下：

```json
{"type": "human", "content": "你好", "name": null, "id": null}

{"type": "ai", "content": "", "tool_calls": [
  {"name": "calculator", "args": {"expression": "1+1"}, "id": "call_1", "type": "tool_call"}
]}

{"type": "tool", "content": "2", "name": "calculator",
 "tool_call_id": "call_1", "status": "success"}
```

跨进程、写日志、做评测回放时，通常存这种结构，再还原成消息对象。

## 7. 常见误区

| 误区 | 正确做法 |
|---|---|
| `invoke({"messages": ["你好"]})` | `HumanMessage("你好")` |
| 工具结果再包成 `HumanMessage` | 用 `ToolMessage` + 正确 `tool_call_id` |
| 随便填 / 省略 `tool_calls[].id` | Action 与 Observation 配对会断 |
| 有 checkpointer 仍每轮手搓全历史 | 一般只传本轮增量，让存储器拼历史 |
| 每次换新 `thread_id` 却期望「记得我」 | 同一会话固定同一个 id |
