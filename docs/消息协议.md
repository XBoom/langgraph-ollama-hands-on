# LangChain / LangGraph 消息协议

> 本文是**本仓库的对照说明**，不单独发布。概念对齐 langchain-core 1.x（本仓锁 langchain-core 1.8.1）。  
> 可运行代码不贴全文：见下方「先跑」与「代码锚点」。

---

## 1. 先跑（建立直觉）

**离线假模型（推荐先跑，无需 Ollama）：**

```bash
poetry run python docs/examples/messages_protocol_demo.py
```

脚本：[`docs/examples/messages_protocol_demo.py`](./examples/messages_protocol_demo.py)  
会演示：① `Human → AI(tool_calls) → Tool → AI`；② 同一 `thread_id` 第二轮只交新句、历史由 `MemorySaver` 拼回。

**真模型交互（需本机 Ollama）：**

```bash
poetry run python -m agent.demo
```

入口：[`agent/demo.py`](../agent/demo.py) — 每轮只提交 `HumanMessage`，`stream` 打印 `model` / `tools` 节点更新。

跑完记住四件事：

1. 对话是带 `type` 的消息对象列表，不是一大段纯字符串。  
2. 调工具时 `AIMessage.tool_calls[].id` 必须等于 `ToolMessage.tool_call_id`。  
3. 每轮通常只交**本轮** `HumanMessage`；旧记录靠 checkpointer。  
4. `thread_id` 决定打开哪一本聊天本。

## 2. 白话：框架在管什么？

### 2.1 为什么不是一个大字符串？

| 白话角色 | 类型 | `type` |
|---|---|---|
| 用户 | `HumanMessage` | `human` |
| 模型（可含 tool_calls） | `AIMessage` | `ai` |
| 工具结果 | `ToolMessage` | `tool` |
| 系统规矩 | `SystemMessage` | `system` |

用户输入要包成 `HumanMessage`：协议要求标明角色。本仓写法见 `agent/demo.py` 里 `stream` / `invoke` 的入参。

### 2.2 `messages` 状态

Agent 状态小本子的核心栏是 `messages`（类型上是 `list[AnyMessage]`，用 `add_messages` **追加**合并）。

```python
agent.invoke({"messages": [HumanMessage(content="你好")]}, config)
```

含义：这次至少交上「用户刚说的这句话」；有 checkpointer 时不会用这几条盖掉整本历史。

### 2.3 checkpointer 与 `thread_id`

| 概念 | 白话 | 本仓哪里 |
|---|---|---|
| checkpointer | 存档/读档；快照叫 checkpoint | `agent/graph.py` 的 `MemorySaver()`；离线示例同上 |
| `thread_id` | 聊天本名字；同 id 接着聊 | `demo.py` 的 `--thread` → `configurable.thread_id` |

| 情况 | 效果 |
|---|---|
| 无 checkpointer | 每轮失忆 |
| 有 checkpointer 但乱换 `thread_id` | 每次新开一本，也记不住 |
| 同一 `thread_id` | 跨轮连续（见离线示例第 2 轮 / `tests/test_agent.py` 记忆用例） |

术语：`state["messages"]` = 聊天记录；`AnyMessage` = 消息类型统称；`add_messages` = 追加合并规则。

## 3. 类型与字段（对照包，不贴长代码）

```text
BaseMessage
├── HumanMessage / AIMessage / SystemMessage / ToolMessage
├── FunctionMessage / ChatMessage   # 少用
└── *MessageChunk                   # 流式
```

公共字段：`content`、`type`、`name`、`id`、`additional_kwargs`、`response_metadata`。  
`AIMessage` 另有 `tool_calls`（`name` / `args` / `id`）；`ToolMessage` 必填 `tool_call_id`。

手写构造与假模型消费消息列表：[`tests/fakes.py`](../tests/fakes.py)。  
评测如何扫 `tool_calls` / 最终 `content`：[`agent/eval.py`](../agent/eval.py)。

## 4. 一轮工具调用怎么串

```text
HumanMessage
  → AIMessage(tool_calls=[{id, name, args}])   # Action
  → ToolMessage(tool_call_id=同一 id)            # Observation
  → AIMessage(content=最终回答)
```

真跑观察：`agent.demo` 的 `stream_mode="updates"`（跳过 middleware 的 `None` payload；模型节点名是 `model`）。  
离线完整列表打印：`docs/examples/messages_protocol_demo.py`。

可选：`config["recursion_limit"]` 限制模型↔工具来回次数（与协议正交，`demo.py` 已设）。

## 6. 常见误区

| 误区 | 正确做法 |
|---|---|
| `invoke({"messages": ["你好"]})` | `HumanMessage("你好")` |
| 工具结果再包成 HumanMessage | `ToolMessage` + 正确 `tool_call_id` |
| 有 checkpointer 仍每轮手搓全历史 | 只传本轮增量 |
| 换 `thread_id` 却期望记得我 | 同一会话固定同一 id |
| `stream` 里对 `None` payload 调 `.get` | 先判断 `isinstance(payload, dict)`（`demo.py` 已处理） |
